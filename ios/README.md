# Curio — iOS 26

Curio is a native **iOS 26 SwiftUI** app that turns your X (Twitter) bookmarks into a personal research index. It is a full-parity port of the Curio Android app: OAuth2 PKCE login to X, three-phase bookmark sync (Firestore pull → X paginated fetch → Firestore push), dual AI analysis (on-device Foundation Models / cloud xAI Grok / offline keyword classifier), Vision OCR, on-device EmbeddingGemma RAG with cosine vector search, primary-source resolution (arXiv / GitHub / HuggingFace / Crossref DOI), user-created **Spaces** and rule-driven **Smart Spaces**, weekly AI digests, byte-faithful citation export (BibTeX / RIS / CSL-JSON / Markdown / JSON / CSV), Grok image generation, App Intents for on-device agents, a Share Extension for the system share sheet, and BGTaskScheduler background maintenance — all wrapped in an iOS 26 Liquid Glass UI. Targets **iOS 26+, Swift 6** strict concurrency.

## Module architecture (12 modules)

Every module is a folder under `Curio/Curio/`. Dependency order (low → high):

**Domain → Persistence → Networking → Auth → AI → Intelligence → Repository → Theme → Components → Screens → Platform → App.**
(Networking/Auth are siblings; Repository depends on Persistence + Networking + AI + Intelligence.)

| # | Module | Responsibility |
|---|--------|----------------|
| 1 | **Domain** | Pure Foundation value models, enums (rawValue == Kotlin `.name`), repository protocols, `SpaceRule` matching engine + tolerant JSON, root error types. |
| 2 | **Persistence** | SwiftData layer: one `ModelContainer` (`curio_database`), two `@Model`s, `@ModelActor` stores mirroring Room DAOs, versioned migration plan. |
| 3 | **Networking** | URLSession + Codable clients: xAI Grok, X bookmarks/auth, arXiv/Crossref/GitHub/HF, Firestore sync. |
| 4 | **Auth** | PKCE handshake, `ASWebAuthenticationSession`, Keychain `TokenStore`, session state. |
| 5 | **AI** | Backend-selection chain (Foundation Models / cloud xAI / offline keyword), language gate, chat prompt builder. |
| 6 | **Intelligence** | Embeddings (download manager + providers + selector), Vision OCR, vector math, source resolver, citation exporter. |
| 7 | **Repository** | Offline-first `BookmarkRepositoryImpl` actor: sync, cloud mirror, smart-spaces, embeddings, curation. |
| 8 | **Theme** | Liquid-glass design system: Cosmic color scheme, typography, motion springs, glass tier ladder. |
| 9 | **Components** | Reusable widgets, brand logo, chrome (top bar/bottom nav/FAB/scaffold), post card, dialogs, markdown renderer. |
| 10 | **Screens** | Eight screens + auth slice + nav enum + pure formatting helpers, reading one shared `@Observable` view model. |
| 11 | **Platform** | DI composition root (`AppEnvironment`), view models + controllers, background tasks, App Intents, Share Extension glue, config/secrets. |
| 12 | **App** | `@main` entry, scene wiring, Firebase configure, BGTask registration, share drain. |

## Requirements

- **macOS** with **Xcode 26**
- **iOS 26 SDK** (Foundation Models, Vision async API, Liquid Glass, modern App Intents)
- **Swift 6** (strict concurrency `complete`)
- [XcodeGen](https://github.com/yonyz/XcodeGen) (the `.xcodeproj` is generated, not committed)
- A `GoogleService-Info.plist` and real secrets (see below) to actually run.

## Build steps

1. **Install XcodeGen** (Homebrew):
   ```sh
   brew install xcodegen
   ```
2. **Generate the Xcode project** from `ios/`:
   ```sh
   cd ios && xcodegen generate
   ```
   This produces `Curio.xcodeproj`. The `CurioShareExtension/Info.plist` is **generated by XcodeGen** from the inline `info:` block in `project.yml` — its absence on disk is expected, not a defect.
3. **Open** `Curio.xcodeproj` in **Xcode 26** on macOS.
4. **Add `GoogleService-Info.plist`** to the **Curio** app target. In the Firebase console add an iOS app with bundle id **`com.curio.app`**, download the plist, and place it at `ios/Curio/GoogleService-Info.plist` so it is bundled as an app resource (verify it appears under *Copy Bundle Resources*). `FirebaseApp.configure()` reads it from `Bundle.main` at launch. **Firestore sync does not work without it.**
5. **Set signing**: set `DEVELOPMENT_TEAM` and code-signing for the `Curio` and `CurioShareExtension` targets (e.g. via a local `.xcconfig` or the Signing & Capabilities pane). `CODE_SIGN_STYLE` defaults to `Automatic`.
6. **Supply configuration** via `.xcconfig` / `Info.plist` keys read by `CurioConfig` — never commit real values:
   - `X_CLIENT_ID` (with `CLIENT_ID` fallback) — X OAuth client id
   - `X_REDIRECT_URI` — e.g. `curio-oauth://callback`; also registered as the `ASWebAuthenticationSession` callback scheme in `CFBundleURLTypes`

   **BYOK — no AI secrets ship in the build.** The xAI Grok key and the HuggingFace token (for the gated EmbeddingGemma ~180 MB download) are supplied by the user at runtime in **Settings** and stored only in the **Keychain** (`TokenStore`), shared via the `keychain-access-groups` entitlement; never in `Info.plist`. OAuth tokens likewise live only in the Keychain.
7. **Select an iOS 26 simulator** (or a device) and **Run**.

### App Intents & Share Extension

- The **9 App Intents + 2 AppEntities** ship **in-app** (registered via `AppDependencyManager` in `CurioApp.init`) — there is **no separate App Intents extension target**. The two real targets are `Curio` and `CurioShareExtension`. The three write intents (add bookmark / add note / toggle favorite) are additionally gated on the Settings toggle **"Allow assistants to modify my bookmarks"** (`TokenStore.isAgentWritesAllowed`, default on), mirroring Android's replacement of its caller allowlist.
- The **Share Extension** (`CurioShareExtension`) receives URL / plain-text shares from the X app and other apps and queues them into App-Group `UserDefaults`; the main app drains the queue on `.active`.

### ChronosFlow interop (reading list / inbox / task handoff)

Curio can hand a bookmark to the companion **ChronosFlow** planner app ("remind me to read later", quick-capture inbox, follow-up task) from the card options sheet and via three App Intents. On Android this rides ChronosFlow's exported ContentProvider; on iOS it uses the platform substitution the two apps already share for their other integrations: Curio appends JSON handoff entries (`curio-handoff.json`, see `ChronosInteropContract`) into the shared App-Group container `group.com.chronosflow.shared`, and ChronosFlow drains the queue with its interop import pipeline. To activate it:

1. The `group.com.chronosflow.shared` App Group is declared in `project.yml` (`entitlements.properties` — the generated `Curio.entitlements` carries it; edit `project.yml`, not the generated file). On a real device the group must be registered to the signing team.
2. `chronosflow` must be in `LSApplicationQueriesSchemes` (already in `Info.plist`) so `ChronosFlowBridge.isAvailable()` can detect the app.
3. ChronosFlow iOS needs a small drain pass for `curio-handoff.json` (same shape as its existing `InteropSync` importer). Until all three are in place the ChronosFlow actions stay hidden (the bridge reports "not installed") and Curio runs standalone.

## Known limitations / TODO-on-Mac

> This codebase was generated and statically verified on Windows, then went through a **doc-grounded API hardening pass** against the official Apple & Firebase documentation, and **now compiles green on macOS** (`xcodebuild … -destination 'generic/platform=iOS Simulator'` → BUILD SUCCEEDED, Xcode 26 / Swift 6 strict concurrency).

### Doc-verified during hardening (fixed where wrong, otherwise confirmed correct)

These were checked against official docs; ✅ = confirmed already-correct, 🔧 = a concrete fix was applied.

- 🔧 **App Intents** — `authenticationPolicy` type corrected from the non-existent `AuthenticationPolicy` to `IntentAuthenticationPolicy` (would not have compiled) on the 4 write/detail intents. ✅ `@Parameter`, `AppEntity`/`defaultQuery`, `EntityStringQuery.entities(for:)`/`entities(matching:)`, `DisplayRepresentation`/`TypeDisplayRepresentation`, `AppShortcut(intent:phrases:shortTitle:systemImageName:)`, `IntentResult & ReturnsValue`, and the in-app `AppShortcutsProvider` + `@Dependency`/`AppDependencyManager` DI pattern all confirmed against docs.
- 🔧 **Swift 6 concurrency** — `Repository/TimeoutSupport.swift` `withTimeout` changed `async rethrows` → `async throws` (Swift 6 rejects `rethrows` when the body throws via `withThrowingTaskGroup`/`group.next()`), and `try` added at both `BookmarkRepositoryImpl` call sites. The actor `Task {}` / `CurrentValueSubject` isolation pattern was reviewed and is correct.
- 🔧 **AuthenticationServices** — deprecated `ASWebAuthenticationSession(url:callbackURLScheme:)` → current `init(url:callback: .customScheme(...))` (iOS 17.4+). ✅ `ASWebAuthenticationSessionError.code == .canceledLogin`, `presentationContextProvider`, `prefersEphemeralWebBrowserSession`, `start() -> Bool` confirmed.
- 🔧 **Core ML** — deprecated synchronous `MLModel.compileModel(at:)` → `await` async overload (`ensureModel()` made `async`, sole call site updated). ✅ `MLModel(contentsOf:configuration:)`, `MLDictionaryFeatureProvider`, `prediction(from:)`, `featureValue(for:)?.multiArrayValue`, `MLMultiArray` float access confirmed.
- 🔧 **Liquid Glass** — `Glass.regular.tint(_:)` confirmed to accept `Color?`, so the `.map`/`??` workaround was simplified to `Glass.regular.tint(tint)`. ✅ `.glassEffect(_:in:)`, `GlassEffectContainer { … }` (no-arg trailing closure), `Glass.regular`, `#available(iOS 26, *)` gating + `.ultraThinMaterial` fallback confirmed.
- ✅ **Foundation Models** — `SystemLanguageModel.default.availability`, the `.unavailable` reasons (`.deviceNotEligible`/`.appleIntelligenceNotEnabled`/`.modelNotReady`), `LanguageModelSession(instructions:)`, `session.respond(to:).content` all confirmed against docs.
- ✅ **Vision (iOS 26)** — value-type `RecognizeTextRequest()`, `recognitionLevel`, `recognitionLanguages: [Locale.Language]`, `usesLanguageCorrection`, `perform(on:) async throws`, `topCandidates(1).first?.string`, and the `VNRecognizeTextRequest` legacy fallback all confirmed.
- ✅ **SwiftData `@ModelActor`** — synthesized `modelContext`/init, `FetchDescriptor(predicate:sortBy:)`, `.fetchLimit`/`.propertiesToFetch`, `fetch`/`insert`/`delete`/`save()` (single-save atomic batches) confirmed.
- ✅ **Firestore (12.x)** — `Firestore.firestore()`, collection/document paths, `getDocuments() async`, `batch()`/`setData(_:forDocument:merge:)`/`commit() async`, `deleteDocument(_:)`, `FieldValue.serverTimestamp()` confirmed.

### Genuinely remaining (require a Mac / device / project asset)

- **Core ML model feature names** — the converted EmbeddingGemma `.mlpackage`'s actual input/output feature names (`text` / `embedding`) and input type are conversion-specific and must match the real model; verify on the Mac.
- **BGTask on Simulator** — link sweep + charging-gated embedding backfill behave differently on the Simulator (no real charging state; submission/launch unreliable). Validate on a real device.
- **GoogleService-Info.plist + real secrets** are required to actually run sync, AI, embeddings, and login — without them those flows no-op or fail gracefully. The committed `GoogleService-Info.plist` is a parseable placeholder; replace it.
- **`CurioShareExtension/Info.plist` is generated** by XcodeGen at `xcodegen generate` time (inline `properties:` in `project.yml`), so it is intentionally not committed.
- **App Intents discovery model** — the in-app `AppShortcutsProvider` is internally consistent; on-device, confirm Siri/Spotlight/Shortcuts discovery is sufficient without a dedicated AppIntents extension target. (`DEPENDENCIES.md` has a stale `CurioIntents` extension column — intents ship in-app.)
- **Entitlements on device** — verify the in-app App Intents read the same keychain-access-group (`$(AppIdentifierPrefix)com.curio.app`) as the UI; `CurioShareExtension` intentionally has no keychain entitlement.
- **SwiftUI layout edge cases** — `CurioChatScreen`'s `Layout`-conforming flow layouts (`Cache == Void`) and `ReaderViewScreen`'s `.fullScreenCover` transition/theme propagation are best confirmed by running on an iOS 26 simulator.
